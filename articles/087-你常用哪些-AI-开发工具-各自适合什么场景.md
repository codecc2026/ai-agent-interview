# 你常用哪些 AI 开发工具？各自适合什么场景？

<!-- growth-hook:v1 -->
“你常用哪些 AI 工具？”——列名字是最没信息量的答法。按场景分层讲：通用对话、编码协作、低代码平台、知识库平台，再说清你在真实项目里怎么组合着用，才是面试官想听的。

## 面试官为什么爱问这题

这是腾讯 AI 后台工程师一面的真题，考的是工具生态认知和按场景选工具的成熟度。很多人答这题就是报一串工具名——"我用过 ChatGPT、Cursor、Dify……"，面试官想听的不是你用过多少，而是你有没有形成自己的工具分层心智，知道不同工具各自解决什么问题。题库给了很好的切法：按场景分成四类，每类说清适合什么，再讲真实项目里怎么组合。前面聊过各种具体工具和平台，这一篇把它们收进一张"工具地图"，也是最后三篇岗位认知题的开篇。

## 一句话先给结论

**比较稳的答法不是罗列名字，而是按场景分层。通常分四类：通用对话与研究类（ChatGPT、Claude、Perplexity）适合快速验证想法、梳理方案、写初稿、做资料总结；AI 编码协作类（Cursor、Claude Code、GitHub Copilot）适合读代码、改代码、补测试、解释代码库结构；低代码 / 工作流平台类（Coze、Dify）适合业务快速验证、工作流编排、知识库接入和多人协作；RAG / 知识库平台类（RAGFlow）适合文档导入、解析、切块、检索和引用链路验证。真实项目里通常按阶段组合使用，而不是只选一种。**

## 核心原理：四类工具，各有所长

### 通用对话与研究类

例如 ChatGPT、Claude、Perplexity。适合快速验证想法、梳理方案、写初稿、做资料总结。这是最常用的"思考伙伴"——项目早期拿来理清思路、对比方案、快速出草稿。Perplexity 这类偏研究的工具在查资料、找出处上有优势。这类工具的特点是通用、上手快，但产出需要你判断和加工，不能直接当最终交付。

### AI 编码协作类

例如 Cursor、Claude Code、GitHub Copilot。适合读代码、改代码、补测试、解释代码库结构。这类工具的关键区分点是形态：**更偏 IDE 内协作的**（如 Cursor、Copilot），适合在写代码时即时补全、小范围修改；**更偏终端里的代码库级 Agent 的**（如 Claude Code），适合跨文件的仓库级理解与修改。前面讲 Code Agent 时说过代码库理解和验证闭环，这些工具正是那些能力的产品化形态。

### 低代码 / 工作流平台类

例如 Coze、Dify。适合业务快速验证、工作流编排、知识库接入和多人协作。价值在"快"——不用写代码就能把 Agent、RAG、Workflow 搭起来给业务看，适合 POC 阶段和业务侧参与。前面讲平台 vs 框架时说过，平台偏应用搭建层和可视化交付，这里是它们在工具地图里的位置。

### RAG / 知识库平台类

例如 RAGFlow。适合文档导入、解析、切块、检索和引用链路验证。这类平台把 RAG 的整条链路做深——如果你要验证"文档解析质量稳不稳、引用链路对不对"，用它比用通用平台更合适。前面讲 RAG 平台选型时说过专精平台在文档链路上的优势，这里是它的工具定位。

| 类别 | 代表工具 | 适合场景 |
| --- | --- | --- |
| 通用对话与研究 | ChatGPT、Claude、Perplexity | 验证想法、梳理方案、写初稿、资料总结 |
| AI 编码协作 | Cursor、Claude Code、Copilot | 读改代码、补测试、解释代码库 |
| 低代码 / 工作流平台 | Coze、Dify | 业务验证、工作流编排、知识库接入、协作 |
| RAG / 知识库平台 | RAGFlow | 文档解析、切块、检索、引用链路验证 |

换成"我要做某件事，该拿哪个工具"，可以这样对号入座：

| 要做的事 | 优先考虑 | 理由 |
| --- | --- | --- |
| 理清一个模糊需求、对比方案 | 通用对话工具 | 快速出草稿和思路，成本低 |
| 在现有代码库里改一个功能 | AI 编码工具 | 理解上下文、直接改代码 |
| 两天内搭个 POC 给业务看 | 低代码平台 | 不用写代码，编排可视化 |
| 验证一批文档的解析和引用 | RAG 专精平台 | 文档链路做深，可核对 |

这张表是工具分层心智的实用形态——遇到任务先问"这属于哪类"，再在同类里选具体工具，而不是在几十个工具里挑花眼。

## 工程实践：真实项目里怎么组合

题库强调：真实项目不会只选一种工具，而是按阶段组合。一个典型路径：

**前期**用通用对话工具梳理方案、对比技术路线、写初稿——快速把想法理清。

**验证阶段**用低代码平台做 POC——快速把 Agent 或工作流搭出来，给业务看、验证价值。

**实现阶段**用 AI 编码工具接手核心链路——读代码、改代码、补测试，提升工程效率。

**后期**把评测、部署和可观测性补齐——这部分前面讲过很多，工具只是辅助，工程纪律才是关键。

```text
方案梳理：ChatGPT / Claude 理清思路、对比方案
   ↓
快速验证：Dify / Coze 搭 POC，给业务看效果
   ↓
核心实现：Cursor / Claude Code 读改代码、补测试
   ↓
链路验证：RAGFlow 验证文档解析和引用链路
   ↓
工程补齐：评测、部署、可观测性
```

要点：每个阶段有每个阶段合适的工具，不是"哪个工具最好"，而是"这个阶段哪类工具最划算"。前面讲框架选型时说过"按阶段选"，工具选择同理。

工具之间还要考虑衔接，前期用通用工具梳理出的方案，能不能顺利变成低代码平台里的配置？POC 验证通过的流程，能不能平滑迁移到代码实现？选工具时不只看单个工具好不好用，还要看它产出物能不能被下一阶段接住。经验值：优先选那些产出可导出、接口开放的工具，别让自己在某个阶段被私有格式锁死，这和前面讲技术选型避免锁死是同一个道理。

### 工具是杠杆，不是替代品

还有一层意识值得在面试里体现：AI 工具放大的是你已有的能力，而不是替你承担判断。用通用工具出草稿，你得能分辨对错；用编码工具改代码，你得能 review 它改得对不对；用低代码平台搭流程，你得知道流程设计得合不合理。工具用得越顺手，越要守住工程判断——评测、可观测、安全边界这些，工具不会替你想清楚。前面讲过那么多工程纪律，不会因为用了 AI 工具就不成立。把这点讲出来，面试官能看出你不是"被工具带着走"的人。

## 追问逐条作答

### 追问一：AI 编码工具里，IDE 内协作和终端代码库级 Agent 怎么选？

看任务范围。IDE 内协作的（Cursor、Copilot）适合写代码时的即时补全、小范围修改，你在写某个函数，它帮你接着写、改几行，上下文是你当前打开的文件。终端里的代码库级 Agent（Claude Code）适合跨文件的仓库级理解和修改，比如"把这个功能从 A 模块迁到 B 模块"这类需要理解整个代码库结构的任务。经验值：小改用工具体感更强、反馈更快；大改用 Agent 更能理解全局。实际可以两者配合。

### 追问二：低代码平台和 RAG 专精平台怎么区分？

看重心。低代码平台（Coze、Dify）能力强、边界宽，Agent、工作流、插件、知识库都能做，适合快速搭出完整应用；RAG 专精平台（RAGFlow）把文档那条链路做深，解析、切块、检索、引用，适合验证和优化知识库链路。如果需要的是完整应用，用低代码平台；如果要死磕知识库的解析和检索质量，专精平台更合适。前面讲 RAG 平台选型时展开过这个判断。

### 追问三：为什么不要只报工具名？

因为面试官考的不是"用过多少"，而是你有没有工具分层的心智。只报名单，说明你只是使用者；说清每类工具解决什么问题、什么场景用哪个、项目里怎么组合，才说明你形成了判断框架。工具会过时、新工具不断出，但"按场景分类、按阶段组合"这个方法不会过时。面试官要的是可迁移的判断力，不是一份会过时的名单。

### 追问四（自补）：通用对话工具产出的东西能直接用吗？

通常不能，要加工和判断。通用工具适合快速验证想法、梳理方案、写初稿、做资料总结——这些都是"半成品"，需要你核实事实、按业务调整、补上具体约束。前面讲幻觉治理时说过模型会出错，"看起来很像真的但细节偏了"，通用工具产出也有这个问题。把它当思考伙伴和草稿工具，而不是最终答案的来源，是成熟的使用方式。

### 追问五（自补）：工具用得多是不是好事？

不一定，关键看是否解决了问题。堆工具会增加切换成本和学习成本，每个工具都有自己的心智模型。经验值：每类工具选一两个用熟，比样样都碰一点更有价值；引入新工具要能说清"它解决了现有工具解决不了什么问题"。前面讲工具治理时说过"工具不是越多越好"，这里对个人工具箱同样成立。

### 追问六（自补）：新工具不断冒出来，怎么保持判断不被带偏？

回到"它解决什么问题"这个根本。新工具出来时先看它属于哪一类、比现有工具多解决了什么问题、切换成本有多高；别因为火就全盘切换，也别因为用惯了就拒绝了解。经验值：保持对工具的关注，但把"工具层"和"方法层"分开——方法是按场景分层、按阶段组合、关注衔接和边界，这些不随工具更替而变；具体工具只是方法的载体。把方法吃透，新工具来了你能快速判断该不该用，而不是被每一波热点牵着走。

## 60 秒面试回答模板

> 我不会只报一串工具名，而是按场景分层。方案梳理和资料总结常用 ChatGPT、Claude 这类通用工具；代码实现和仓库级修改更偏 Cursor、Claude Code、Copilot，其中 IDE 内协作适合小改、终端 Agent 适合跨文件的仓库级任务；业务验证和工作流编排用 Dify、Coze；知识库链路验证更适合 RAGFlow 这类专精平台。真实项目里我不会只选一种，而是按阶段组合：前期用通用工具理清方案，用低代码平台做 POC 给业务看，再用编码工具接手核心实现，知识库链路用专精平台验证，最后补齐评测、部署和可观测性。我关注的是不同工具解决什么问题，而不是哪个更火。

## 加分项

- 按四类场景组织，每类说清适合什么。
- 区分 AI 编码工具的两种形态，显示真实使用经验。
- 给出真实项目按阶段组合的路径，不是孤立的工具清单。
- 点出考的是工具分层心智，不是用过多少。

## 常见误区

- **只报工具名**：没有分层和场景，显得只是使用者。
- **按热度选工具**：火的未必适合当前场景，要看解决什么问题。
- **工具堆得越多越好**：切换和学习成本也是成本，用熟几个更有价值。
