# Agent 上线后该盯哪些指标？只看成功率为什么不够

<!-- growth-hook:v1 -->
Agent 上线后只看“成功率”，等于蒙着眼睛开车。一个任务分成五步，整体成功一次不代表每步都稳——哪一步在反复重试、哪一步在大量超时，这些分布才是真正指导优化的信号。

## 面试官为什么爱问这题

这题高频，考的是你有没有从 Demo 思维切换到生产运维思维。做 Demo 时只要"能跑通"就算成功，上线后要管的是一整套指标——效果好不好、快不快、稳不稳、贵不贵、可不可控。面试官想听你能不能把运维指标系统性地分成几类，并且指出多步骤 Agent 特有的观测需求：只看"最终失败了"没用，得知道失败发生在哪一步。前面单独聊过上线前关心的工程指标，也聊过可观测性体系怎么建；这一篇聚焦"部署运维阶段日常盯什么"，把指标按类梳理清楚。

## 一句话先给结论

**Agent 运维至少看五类指标：效果指标（任务完成率、用户满意度、引用正确率）；性能指标（首 token、端到端延迟、P95/P99）；稳定性指标（调用成功率、超时率、重试率、失败率）；成本指标（token 消耗、工具调用成本、单任务平均成本）；治理指标（人工接管率、审计日志完整性、异常任务复盘效率）。如果是多工具、多步骤 Agent，还要看每一步的成功率和卡点分布，否则只能知道"最终失败了"，却不知道失败发生在哪一层。**

## 核心原理：五类指标

### 效果指标：事情办成了没有

任务完成率、用户满意度、引用正确率。这是最根本的一类，系统存在的意义是把事办成。效果指标回答"用户的问题解决了吗、答案可靠吗"。多步骤任务里，完成率要定义清楚什么叫完成，是最终输出就算，还是经过校验确认才算。

### 性能指标：快不快

首 token、端到端延迟、P95/P99。首 token 影响体感，即多久看到第一个字；端到端延迟是总耗时；P95/P99 是分位数，表示 95% 和 99% 的请求在这个时间内完成。为什么看分位数而不是平均值？因为平均值会被少数极慢的请求掩盖，P95/P99 才能暴露长尾问题。前面讲性能瓶颈定位时说过看 wall time 分布，分位数是另一个看延迟的视角。

### 稳定性指标：稳不稳

调用成功率、超时率、重试率、失败率。这类指标看系统的可靠性。重试率尤其值得看——它常常是链路不健康的早期信号：某个工具开始不稳定，重试率先升高，然后失败率才跟上。盯重试率能提前发现问题。

### 成本指标：贵不贵

token 消耗、工具调用成本、单任务平均成本。前面讲成本优化时说过按层拆解花费，落到运维上就是这些指标的日监控。单任务平均成本是综合指标——把 token 和工具成本都摊到每个任务上，看趋势有没有恶化。

### 治理指标：可不可控

人工接管率、审计日志完整性、异常任务复盘效率。这类指标回答"系统出问题时能不能管住"。人工接管率高说明自动化程度不够或效果不行；审计日志完整性是合规要求；复盘效率决定出问题后能不能快速改进。前面讲幻觉治理和内网审计时都提过这些，这里把它们归到运维指标。

| 指标类别 | 具体指标 | 回答什么 |
| --- | --- | --- |
| 效果 | 任务完成率、用户满意度、引用正确率 | 事办成没有 |
| 性能 | 首 token、端到端延迟、P95/P99 | 快不快 |
| 稳定性 | 成功率、超时率、重试率、失败率 | 稳不稳 |
| 成本 | token、工具成本、单任务平均成本 | 贵不贵 |
| 治理 | 人工接管率、审计完整性、复盘效率 | 可不可控 |

这五类都要采集，但不同阶段重点不同：

| 阶段 | 最看重的指标 | 原因 |
| --- | --- | --- |
| 早期验证 | 效果指标 | 先证明系统能把事办成 |
| 规模化 | 稳定性、成本 | 量一大，可靠性和成本被放大 |
| 强合规行业 | 治理指标 | 审计和可追责是硬要求 |
| 面向用户的产品 | 性能指标 | 延迟直接决定体验 |

### 多步骤 Agent 特有的：每一步的成功率和卡点分布

这是 Agent 运维区别于普通应用的关键。一条 Agent 链路有很多步——检索、多次工具调用、模型决策、校验。如果只看最终成功/失败，你只知道"最终失败了"，不知道败在哪一步。所以要按步骤看成功率和卡点分布：哪一步失败率最高、哪一步耗时最长、任务最常卡在哪个环节。

前面讲可观测性时说过"问题多在中间步骤"，这里正是它的指标化落地。卡点分布能直接指出优化重点——如果 80% 的失败集中在某个工具调用，优化那个工具的收益远大于泛泛地调模型。

## 工程实践：把指标做成一张运维看板

落到运维，五类指标要能在一张看板上看到，并且能下钻。

**分层看。** 大盘看整体趋势，包括完成率、延迟、成本、错误率；下钻到具体环节，看哪一步、哪个工具、哪个模型。只有大盘没有下钻，发现异常也定位不到；只有细节没有大盘，发现不了系统性变化。

**看趋势和突变。** 指标的价值在对比——和昨天比、和上周比、版本变更前后比。单点数字意义有限，趋势图才有信息。前面讲可观测性时说过版本字段的重要性，指标看板也要能按版本切分，才能看出"换 Prompt 之后完成率掉了"。

**设告警阈值。** 关键指标要有告警——错误率超多少、P99 延迟超多少、单任务成本涨多少，触发告警。阈值要基于历史基线设，不能拍脑袋。

```python
# 伪代码：按步骤统计成功率和耗时，做卡点分布
def step_report(traces):                          # traces：一批请求的链路数据
    stats = {}
    for trace in traces:
        for step in trace.spans:                  # 遍历每一步
            bucket = stats.setdefault(step.name, {"ok": 0, "fail": 0, "durations": []})
            if step.error:
                bucket["fail"] += 1               # 失败计数
            else:
                bucket["ok"] += 1
            bucket["durations"].append(step.duration)
    return rank_by_failure_and_time(stats)        # 业务侧：按失败率和耗时排序

# traces / rank_by_failure_and_time 为业务侧或观测库实现
```

要点：按步骤聚合成功率和耗时，再排序找出卡点。`rank_by_failure_and_time` 是业务侧实现。这段代码是"卡点分布"的具体算法——把中间步骤的失败和耗时统计出来，优化重点自然浮现。

## 追问逐条作答

### 追问一：这五类指标哪类最重要？

看阶段和目标，没有绝对答案。早期验证阶段，效果指标最重要，先证明能办成事；规模化阶段，稳定性和成本变得关键，因为量大之后可靠性和成本都被放大；涉及合规的行业，治理指标优先。经验值：别五类平均用力，按当前阶段和资源选重点，但都要有基础的采集，别等需要时才发现没数据。

### 追问二：为什么要看 P95/P99 而不是平均延迟？

因为平均值会掩盖长尾。一百个请求里九十九个很快、一个极慢，平均可能还好，但那个极慢的请求用户感受极差。P95/P99 看的是"绝大多数请求的最坏情况"，能暴露长尾问题。前面讲性能定位时关注 wall time，这里用分位数看延迟分布，两者都是避免被平均值误导。经验值：对外的用户侧系统更看重 P95/P99，因为它直接关系大多数用户的体验下限。

### 追问三：为什么重试率值得单独看？

因为它是链路不健康的早期信号。某个工具或模型开始不稳定，最先表现为重试变多——系统自动重试把问题暂时掩盖了，成功率看起来还行。如果只看成功率，等问题严重到重试也救不回来、失败率上升时才发现，已经晚了。盯重试率能提前预警。前面讲成本排查时说过盲目重试浪费钱，这里是它的另一面：重试率本身也是健康指标。

### 追问四（自补）：多步骤 Agent 的"每步成功率"怎么采集？

靠步骤级埋点。每一步开始和结束时记录成功/失败、耗时、步骤名，聚合时按步骤名分组统计。这要求链路里的每个节点都有唯一标识——前面讲可观测性时说过要给每个 span 打点，这里就是那些 span 的聚合。经验值：步骤命名要稳定、有语义，别用随机的 ID，否则聚合时归不到一起，看不出卡点分布。

### 追问五（自补）：指标和评测有什么区别？

指标是线上持续采集的运行时数据，评测是离线用固定数据集做的质量检验。指标告诉你"现在系统跑得怎么样"，评测告诉你"这个版本质量够不够"。两者互补：指标负责发现异常，比如完成率掉了；评测负责定位原因，用评测集复现问题、确认是哪个改动导致的。前面讲幻觉治理时提过 badcase 回灌和线上监控配合，那也是指标与评测协作的例子。上线前的评测决定是否放行，上线后的指标决定要不要及时回滚，两者守的是不同关口。

## 60 秒面试回答模板

> 运维至少看五类指标。效果：任务完成率、用户满意度、引用正确率，看事办成没有；性能：首 token、端到端延迟、P95/P99，看快不快，用分位数避免平均值掩盖长尾；稳定性：成功率、超时率、重试率、失败率，其中重试率是早期预警信号；成本：token、工具成本、单任务平均成本；治理：人工接管率、审计完整性、复盘效率，看可不可控。多工具多步骤 Agent 还要看每一步的成功率和卡点分布，否则只知道最终失败不知道败在哪一步。落地我会做一张能下钻的看板，分层看、看趋势、按版本切分，并给关键指标设基于基线的告警。

## 加分项

- 五类指标分类清楚，每类回答一个维度。
- 解释 P95/P99 的价值，不用平均延迟被长尾误导。
- 点出重试率是早期预警信号，显示运维敏感度。
- 强调多步骤要看每步成功率和卡点分布，落到 Agent 特性。

## 常见误区

- **只看最终成功失败**：多步骤 Agent 会不知道败在哪，必须看每步。
- **用平均延迟代替分位数**：平均值掩盖长尾，P95/P99 才反映体验下限。
- **忽略重试率**：重试率升高是链路不健康的早期信号，别等失败率上来才发现。
